# Памятка по проекту

Помощник для Escape from Tarkov: подсказывает, что нужно для квестов, убежища
и обменов. WPF, .NET 8, без сторонних NuGet-пакетов.

## Где что лежит

| Что | Где |
|---|---|
| Исходники | `TarkovHelper/` |
| Утилиты для отладки разбора | `tools/` — собираются из тех же файлов, что и программа |
| Тексты выпусков | `docs/releases/` |
| Готовые версии | только на GitHub, в репозитории их нет |
| Профиль игрока, кеш базы, журналы OCR | `%AppData%\TarkovHelper\` |

## Данные игрока живут в `%AppData%\TarkovHelper`

`progress.json` — профили: уровень, фракция, сданные и активные квесты, уровни
станций убежища, опись схрона. Файл переписывается при каждом запуске и после
каждой правки. Перед опасными операциями программа кладёт рядом копию
(`progress.json.bak-*`).

**Запуск программы из оболочки Claude пишет профиль не туда.** Команды в сессии
выполняются внутри контейнера приложения Claude, запись в `AppData\Roaming`
перенаправляется в его песочницу, а запущенный оттуда процесс наследует
контейнер. В итоге помощник читает и пишет
`%LocalAppData%\Packages\Claude_<id>\LocalCache\Roaming\TarkovHelper\`, а не
настоящую папку, и работа целой сессии проходит мимо профиля игрока. Так
потерялись месяц сканирований: профиль с 35-м уровнем и описью схрона осел в
песочнице, а запущенная ярлыком программа открыла пустой настоящий файл.

Поэтому: **проверять изменения запускает игрок, ярлыком `TarkovHelper.lnk`.**
Если программу всё же запустили из сессии — помнить, что её правки останутся в
песочнице, и переносить `progress.json` руками.

Чтение профиля из сессии тоже обманчиво: по пути `AppData\Roaming` отдаётся
копия из песочницы, и она может быть старше настоящей на недели.

### Как из сессии всё-таки попасть в настоящую папку

Дочерний процесс наследует контейнер, но не через `explorer.exe`: он уже
запущен от имени пользователя, и то, что он открывает, выполняется снаружи.
Значит порядок такой — положить сценарий на обычный диск (перенаправление
накрывает только `AppData`), запустить его проводником, а результат забрать из
файла рядом со сценарием:

```powershell
Start-Process explorer.exe -ArgumentList '"D:\...\script.cmd"'
```

Внутри сценария `%APPDATA%` уже настоящий. Этим же способом надо запускать и
саму программу, если её запускает сессия, — иначе она снова уйдёт в песочницу.

Проверять результат надо тем же путём: прочитанное из сессии покажет копию, а
не то, что увидит игрок.

## Сборка и выпуск

```
dotnet publish TarkovHelper -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
gh release create vX.Y.Z <путь к publish\TarkovHelper.exe> --title "TarkovHelper X.Y.Z" --notes-file docs/releases/X.Y.Z.md
```

Версия — в `TarkovHelper.csproj`, поднимать перед тегом. Текст выпуска писать в
`docs/releases/` и оттуда же отдавать в `--notes-file`: так он остаётся в
репозитории. Собранные `.exe` по папкам не раскладывать — их хранит GitHub.

## Чего делать нельзя

**Не читать память игры, не внедряться в процесс, не перехватывать трафик.**
За это выдаёт бан BattlEye. Разрешено только пассивное: снимки экрана, журналы
игры в `<игра>\Logs`, имена файлов скриншотов.

**Не брать данные из SPT.** BSG судится с проектом, их дамп — производное от
ресурсов игры. Источник базы — `json.tarkov.dev`. Исключение: русская локаль
SPT, но она датируется мартом 2025 и отстаёт — см. ниже.

**Карты не класть в репозиторий.** Лицензия проекта GPL-3.0, игровые ресурсы под
неё не попадают; карты берём только у тех, кто их лицензирует, и держим в кеше
пользователя.

**Не расшифровывать зашифрованный ответ tarkov-market.**

## Откуда берутся названия и почему они врут

- `json.tarkov.dev/{pve|regular}/{items,tasks,barters,hideout,maps}` — состав,
  цели, карты, цены. Данные свежие.
- GraphQL `api.tarkov.dev` — **лежит (HTTP 422)**, а это единственный источник
  официальных русских имён.
- Русская локаль SPT — имена, описания и цели заданий. **Датируется мартом
  2025**: переработанные задания описаны по-старому, и программа честно пишет
  об этом под списком.
- Русская вики — нынешние имена. По ней же чинится нумерация частей цепочек:
  номер берётся из английского заголовка (`The Punisher - Part 1`), потому что
  он совпадает с клиентом, а локаль нумерует по-своему.

`GameData.CurrentSchema` поднимать при каждом изменении набора полей — иначе у
игрока останется старый кеш без них.

## Распознавание

- Встроенный `Windows.Media.Ocr` — быстрый и офлайн, но на коротких русских
  словах ошибается («БАДы» → «6AAbl»).
- Yandex Vision OCR — включается в настройках, ключ хранится в `progress.json`
  (в репозиторий не попадает). Списки квестов (F11) читает сразу, предмет под
  курсором (F9) — только если встроенный не справился. Схрон по скриншотам —
  только облаком: подписи в ячейках слишком мелкие.
- Ограничение сервиса: один синхронный запрос в секунду, около 0,13 ₽ за кадр.
