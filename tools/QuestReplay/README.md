# QuestReplay — прогон разбора списка квестов по логу

Проверять сопоставление квестов в игре дорого: надо зайти к торговцу, нажать
клавишу и глазами сверить результат. А `quest-ocr-debug.log` хранит ровно то,
что прочитал OCR, — значит те же строки можно прогнать через боевой
`QuestMatcher` сколько угодно раз.

```bash
dotnet build tools/QuestReplay -c Release
./tools/QuestReplay/bin/Release/net8.0-windows10.0.19041.0/QuestReplay.exe
```

Первый аргумент — путь к логу (по умолчанию `%AppData%\TarkovHelper\quest-ocr-debug.log`),
второй — сколько последних сканов прогнать (по умолчанию один).

Проект компилирует `QuestMatcher.cs`, `ItemMatcher.cs` и модели прямо из
`TarkovHelper`, копий кода нет: проверяется то же самое, что работает в игре.

Статусы («завершено» / «активно!») в логе не сохраняются — игра пишет их
отдельными строками, а они отфильтровываются до записи. Поэтому в прогоне все
строки идут «без статуса»: он проверяет узнавание названий, а не разбор
статусов.

## Что этот прогон уже поймал

Русский движок OCR читает номер части как букву: «Врачебная тайна. Часть З»
вместо «Часть 3», «Часть Б» вместо «Часть 5». Строка с ошибкой набирала
0.88 против *соседней* части цепочки и забирала её себе, а правильный ряд
оставался ни с чем — из четырнадцати рядов узнавалось пять. После разбора
по рядам (обе прочитки одной строки вместе) и сверки номера части отдельно
узнаётся девять; остальное — задания, которых нет в базе tarkov.dev.
